# Duva serves MCP itself, signed in through its user pool, and its tools act as the human's mailbox agent

Duva is a remote MCP server, so an MCP client such as Claude Code or Claude Desktop works with a human's mail. One endpoint per deployment, `<API URL>/mcp` on the API's own domain, speaks MCP's Streamable HTTP without sessions, answering each POST with JSON, from a Lambda that API Gateway invokes with the API's ARN as its source, as it invokes the API's. A client signs in with the human's Duva account through OAuth with the deployment's user pool (ADR-0010). Nicklas chose MCP over OAuth with Cognito on 2026-10-07 (#120, #124), with the research in `docs/research/agentcore.md` (#121), which found AgentCore Gateway's OpenAPI targets can't take Duva's contract and send one credential for everyone. This replaces ADR-0009's "There is no MCP server".

Every tool reaches the human's own mailbox agents (ADR-0027). `askAgent` and `giveAgentTask` hand one a turn in the same conversation as Ask your agent; the first waits up to 20 seconds for its answer, within API Gateway's 30, and the second doesn't wait. The run goes on in the conversation Lambda, which the MCP Lambda invokes without waiting. The other tools are the operations the mailbox agent has as its own tools, generated from the OpenAPI contract with the mailbox as an input (ADR-0009), and each call is the mailbox agent's, made with a run token of its own (ADR-0027) that ends with the call. So a tool does only what the agent may do in that mailbox, at the sponsor access its owner set (ADR-0015, ADR-0024), what it does is attributed to it and carries the disclosure, and its sends wait for the owner's approval as the agent's do. What the human asks is their own turn. The app is software acting for the human, an agent in ADR-0001's sense, and the mailbox agent is the identity that already has their limits. An app a human wants as an agent of its own asks for access instead (ADR-0024).

Cognito's discovery document names no registration endpoint and no PKCE method, its dynamic client registration has no API or CloudFormation property to switch it on, and a user pool takes at most 20 managed login styles, one per app client, so it can't give each MCP client an app client of its own (docs/aws.md). So the stack gives MCP clients one app client, whose only callback is the MCP endpoint's, and Duva is the authorization server they see. Its document, at `/.well-known/oauth-authorization-server` on the API's domain, names Duva's own registration, authorize and token endpoints under `/mcp/`, and PKCE with S256. A client registers with Duva, as RFC 7591 has it, with no secret, and Duva keeps its name and redirect URIs. Its sign-in goes through Duva's authorize endpoint, which first asks the human to allow the app, naming it and the host it sends them back to, since managed login may let a human with a session through without a page, and then to managed login for the MCP app client, with the client's own PKCE challenge, back to Duva's callback, then on to the client's redirect URI. Its token requests go through Duva to managed login's token endpoint, which checks the client's PKCE verifier; a code goes only to the client and redirect URI it was given for, once. The protected resource document, at `/.well-known/oauth-protected-resource/mcp`, names Duva's API as the authorization server, and a call without a valid token answers 401 with a `WWW-Authenticate` that points there.

The MCP endpoint takes only access tokens issued to the MCP app client, and the API's authorizer takes only the web app's and the CLI's. An MCP client's session therefore reaches no operation of the API itself, so it can't approve the sends it asks for, or do as the human anything the mailbox agent may not.

## Considered options

- AgentCore Gateway in front of the API. Rejected in #121: its OpenAPI targets can't take Duva's contract, which uses `oneOf`, `anyOf` and `allOf`, and it sends one credential, so each human's would need an interceptor Lambda, with Duva still writing the code behind the tools.
- Tools that act as the human through MCP. Rejected: an app would then send as the human without approval or disclosure, and limits on what it may do would need a second set of permissions beside sponsor access.
- An app client in the user pool for each MCP client that registers. Rejected: each needs a managed login style to show its sign-in, and a user pool takes 20.
- The one app client with each MCP client's redirect URIs added to it. Rejected: Cognito matches a redirect URI exactly, port included, Claude Code's port changes, and an app client takes 100.
- Cognito's own dynamic client registration. Not possible yet: it can be switched on only in the console, and gives an app client per registration too.
- The MCP SDK's server. Rejected: it brings Express and Hono, and the stateless JSON protocol Duva speaks is a few methods. Tests drive the endpoint with the SDK's client.

## Consequences

- Anyone can register, as MCP clients expect, and a registration is only an item in the table, kept 60 days past its last sign-in or renewal. A registered client gets a human's tokens only once the human allows it on Duva's page, which no other site may frame, so a sign-in link the human didn't start is the phishing risk any open registration has, and the page says to allow only an app they are adding themselves.
- Each refresh token managed login gives is kept by its hash beside the client it went to, and renews only for that client.
- The MCP endpoint and its OAuth endpoints aren't operations of the OpenAPI contract, as downloads and Ask your agent aren't: they answer MCP's and OAuth's own formats. The tools of Duva's own, which list the human's mailboxes and ask the agent, read what Ask your agent reads. Every tool that acts in the mail is one of the contract's operations.
- Managed login's tokens pass through Duva's token endpoint, and Duva keeps none but the refresh tokens' hashes.
- What an app does through the tools shows in the mailbox agent's activity, not told apart from what the agent did in Ask your agent.
- Asking takes the spend cap, pause and access checks of Ask your agent, and refuses as it does. Where AgentCore isn't, the tools still work, and asking is refused.
- Settings, Preferences shows the endpoint's URL and how to add it to Claude Code and Claude Desktop, to a human with a mailbox.
